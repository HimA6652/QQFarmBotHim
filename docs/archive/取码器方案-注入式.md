# 取码器（注入式）· 流程 / 调用 / 生命周期

> **已归档（2026-10-27）**：本文描述的是「本机取码器」时期的方案，**未在现行版本中启用**，请勿据此实施。
> 现状：账号登录走 NapCat 扫码登录；取码器相关代码（`fetcher/`、`core/src/controllers/local-code-routes.js`）作为功能储备保留，未接入主程序。
> 文档目录与现状说明见 [docs/README.md](../README.md)。

- 实现：`fetcher/code-fetcher.mjs`（约 300 行）+ `fetcher/napcat/`（NapCat 最小注入后端，82MB）
- 面板侧：`panel/panel.ps1` 的 `/api/code/*` 四个端点 + 面板页面「扫码取码器」卡片
- 主程序侧：`core/src/controllers/local-code-routes.js`（本机写账号，回环 + 共享令牌）
- 状态：**编排链路已打通并实测；注入后 NapCat Shell 未加载（QQ 构建兼容问题），待解**

## 1. 整体思路

借鉴 NapCat：把 `NapCatWinBootMain.exe` 注入 QQ，让 NapCat 在我们控制的进程里跑起来，
再由它的插件调用 **QQ 内部的 OpenAuth** 换取小程序 code。

与 NapCat 官方用法的区别：**只做取码，一次一命**。

```
面板(3100)
  │  ① POST /api/code/start {mode, accountId}
  │  ② spawn: node fetcher/code-fetcher.mjs --port 8460 --qq <QQ.exe>
  ▼
取码器进程(8460)  ──③ NapCatWinBootMain.exe QQ.exe hook.dll──►  QQ(被注入)
  │                                                              │
  │  ④ GET  /state  ← 面板轮询（含二维码 dataURL）                 │
  │  ⑤ 等扫码 → 登录态                                             │
  │  ⑥ 调 openauth 插件 /miniapp ────────────────────────────────►│ OpenAuth
  │  ⑦ 拿到 code → state.phase=code                                │
  ▼
面板 ⑧ POST /api/code/apply {mode, accountId}
        └─► 主程序 /api/local/code-account（回环 + 令牌）→ 建档/换码 → 启动账号
取码器 ⑨ 杀 QQ 进程树 → 退出（端口 8460 释放）
```

## 2. 取码器进程

### 2.1 职责（只做四件事）

1. 拉起 `NapCatWinBootMain.exe`（带 5 个 `NAPCAT_*` 环境变量），等 WebUI `6099` 就绪
2. 取二维码并渲染成 dataURL（借用主程序 `node_modules/qrcode`）
3. 轮询登录状态；登录后调插件取 code
4. 无论成功/失败/超时/取消，**杀掉 QQ 进程树并退出**

### 2.2 状态机

| phase | 含义 | 面板表现 |
|---|---|---|
| `booting` | 拉起 QQ + 等 6099 | "正在拉起 QQ…" |
| `qr` | 二维码已就绪 | 显示二维码 |
| `scanning` | 已出码，等手机确认 | 显示二维码 + 提示 |
| `logged` | 已登录，正在取码 | "已登录，正在取码" |
| `code` | 已拿到 code | 可点「写入/更新账号」 |
| `done` | 收尾完成（已杀 QQ） | 会话结束 |
| `error` | 失败（附原因） | 显示错误 |
| `cancelled` | 用户取消 | 会话结束 |

### 2.3 命令行参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--port` | `8460` | 取码器状态服务端口（仅 127.0.0.1） |
| `--appid` | `1112386029` | 小程序 appId（QQ 农场） |
| `--timeout` | `180` | 总超时（秒），到点自动清理退出 |
| `--qq` | 自动解析 | QQ.exe 路径；未给则注册表 → `fetcher/qqpath.txt` |
| `--napcat-port` | `6099` | NapCat WebUI 端口（内部使用） |

### 2.4 状态服务（只在本机回环）

| 方法 | 路径 | 返回 |
|---|---|---|
| GET | `/state` | `{phase, qr, qrPng, uin, nickname, code, error, elapsedSec, attempts}` |
| POST | `/cancel` | 立即走清理并退出 |
| GET | `/health` | `{ok, pid}` |

> 设计取舍：取码器**不反向调用面板**，只暴露 `/state` 供轮询。这样它不需要知道面板地址，
> 也不会因为面板重启而失败。

## 3. 触发时机（两种入口，同一流程）

| 场景 | 入口 | mode | 结果 |
|---|---|---|---|
| **新增账号** | 面板「新增账号 → 扫码取码」 | `new` | 用 code 建新账号并启动 |
| **失效账号重登** | 账号卡片「重新登录」；或自动补码在池空时触发 | `refresh` + `accountId`（或按 uin 兜底） | 更新该账号 code → 重启 |

两种情况走的是**同一个取码器、同一套端点**，只有 `mode` 不同。

---

## 4. 面板 ↔ 取码器 的调用方式

| 端点 | 方向 | 说明 |
|---|---|---|
| `POST /api/code/start` | 面板 → 取码器 | 起进程（单实例互斥：8460 已占用则拒绝） |
| `GET /api/code/state` | 面板 → 取码器 | 透传 `/state`（含二维码） |
| `POST /api/code/cancel` | 面板 → 取码器 | 调 `/cancel` → 兜底杀进程 |
| `POST /api/code/apply` | 面板 → 主程序 | 读 `data/local-api-token.txt`，POST `/api/local/code-account` |

面板**不接触** NapCat 的 6099、不碰 QQ 进程，只做"起进程 / 读状态 / 写账号"三件事。

主程序侧的本机接口：

```
POST /api/local/code-account
{ token, mode: 'new'|'refresh', accountId?, code, platform, uin?, name? }
→ { ok, data:{ accountId, created, name, uin, started } }
```
安全边界：只接受 `127.0.0.1/::1` 来源 + 共享令牌（`data/local-api-token.txt`，首次启动生成）。

## 5. 生命周期管理

| 环节 | 规则 |
|---|---|
| 单实例 | 同一时刻只允许一个取码会话（QQ 单实例，且 8460 端口互斥） |
| 超时 | 默认 180s（`--timeout`），到点强杀并 `phase=error` |
| 成功 | 拿到 code 后 1.2s 内 `phase=done` → `taskkill /T` 杀 QQ 进程树 → 进程退出 |
| 失败/取消 | 立即杀进程树 → 退出 |
| 兜底 | `process.on('exit'/'SIGINT'/'SIGTERM')` 都尝试 `taskkill`；面板 `cancel` 再兜一层 |
| 残留 | 面板「取消并结束」会先调 `/cancel`，再按 pid 文件与端口占用者补杀 |

## 6. 边界条件与已知风险

| # | 边界 | 处理 |
|---|---|---|
| B1 | **注入失败**（QQ 构建不兼容） | 取码器会在 `--timeout` 后报 `NapCat WebUI 未就绪`，并清理进程 |
| B2 | QQ 未安装/路径变化 | 面板先解析（注册表 → 常见路径 → `fetcher/qqpath.txt`），再 `--qq` 传给取码器 |
| B3 | 同一账号已在别处登录 | 取码器拉起的 QQ 登录会互踢；建议重登前先确认该号不在桌面 QQ 上 |
| B4 | 扫码超时/拒绝 | `phase=error`，不重试（避免反复起 QQ） |
| B5 | 面板非管理员 | NapCat 注入通常需要提权；请用计划任务或「以管理员身份运行」启动面板 |
| B6 | 二维码过期 | QQ 二维码有时效；过期后需重新开始一次会话 |
| B7 | code 时效 | 取到后尽快写入（面板一键 apply），不要长时间搁置 |

## 7. 实测结论（2026-10-21）

| 环节 | 结果 | 证据 |
|---|---|---|
| 面板 → 取码器（起进程） | ✅ | `POST /api/code/start` → `{ok:true}`，fetcher pid 写入 `panel/run/fetcher.pid` |
| 取码器 → QQ（注入链） | ✅ 拉起 | 日志：`[boot] NapCatWinBootMain pid=25872 qq=D:\ProgramData\QQ\QQ.exe`，QQ 进程起 |
| QQ → NapCat WebUI（6099） | ❌ | 180s 内 6099 未监听，`phase` 停在 `booting` |
| 二维码 / 登录 / 取码 | ⏸ 未到达 | 依赖上一环 |
| 清理 | ✅ | 取消后无 QQ/NapCat 残留；8460 释放 |
| 主程序本机写账号接口 | ✅ | `/api/local/ping` → `{ok:true, tokenReady:true}`，令牌 `data/local-api-token.txt` 48 字节 |

**真正的阻塞点（2026-10-21 12:51 定位）**：被我们拉起的 QQ **自己崩了**，不是注入逻辑的问题。

启动器完整输出（`logs/fetcher-boot.log`）：

```
Boot Command:"D://ProgramData//QQ//QQ.exe" --enable-logging
[NapCat Backend] Main Process ID:22188
Creating pipe: \\.\pipe\NapCat_22188
[NapCat Backend] Process resumed
Process exited.            ← 注入成功后 QQ 立刻退出
```

同期 Windows 事件日志（12:51:43 / 12:51:46 / 12:51:48 连续三条）：

```
出错应用程序名称： QQ.exe，版本： 9.9.36.53644
出错模块名称： KERNELBASE.dll  异常代码： 0xc06d007f
```

`0xc06d007f` = 延迟加载的模块找不到（Electron 初始化 GPU/renderer 失败）。
**同一份程序由人手动启动完全正常**，由本工具/后台任务拉起就崩 —— 说明差异在**进程启动上下文（交互桌面/窗口站）**，
不在 QQ 构建，也不在 NapCat 版本。这也解释了为什么同一个部署包在另一台电脑上流畅可用。

### 因此取码器的使用前提

1. **必须由桌面会话启动**：双击 `启动控制面板-Web.bat`（或用计划任务 `QQFarmBotS-Panel`），
   不要用远程/后台方式直接拉起面板——否则 QQ 起不来，取码一定失败；
2. 取码器已内置「启动前关闭已有 QQ」：QQ 是单实例，已有实例会让注入实例立即退出（`Process exited.`）；
3. 若仍失败，看 `logs/fetcher-boot.log` 的最后几行即可判断是"QQ 没起"还是"注入没完成"。
