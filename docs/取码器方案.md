# 自动取码器（Code Hub）方案

- 目标：QQ 农场账号被顶下线 / 换设备 / 换地点后，**不再需要人工重新抓包**即可拿到新的登录 Code
- 适用：QQFarmBotS（SnowLuma 宿主 + 主程序）
- 状态：**设计稿，待确认后实施**

---

## 0. 先说清楚物理约束（决定方案形态）

Code 只能由**登录过农场小程序的那个 QQ 客户端**生成（`qq.login()` → 网关 URL 里的 `code`）。
它不存在"服务端凭空换码"的可能。所以"不用每次抓包"能实现，靠的不是消灭抓包，而是三件事：

1. **抓包通道常驻化**：手机/设备配一次代理，之后**每次打开农场自动入池**（用户无感）
2. **码池化**：同一 uin 保留最近若干个有效 Code，被踢时立刻取用
3. **自动编排**：踢下线事件 → 自动取码 → 自动重启账号；池空时明确提示"打开一次农场"

> 落点：**日常 0 操作**（只要设备代理不动、偶尔打开农场）；**被踢后 0 操作**（池里有码就直接恢复）。

## 1. 整体架构

```
            ┌────────────── 手机 / 其它设备（QQ 登录农场）──────────────┐
            │   Wi-Fi 代理 → 192.168.x.x:18000 或 Tailscale IP:18000    │
            └───────────────────────────┬──────────────────────────────┘
                                        │ CONNECT/WS
                                 ┌──────▼───────┐
                                 │ CaptureHub   │  常驻 MITM（只解 *.nqf.qq.com 等目标域）
                                 │ 多通道/自续期 │  证书 + 端口保持稳定
                                 └──────┬───────┘
                                        │ code + openID (+ platform/os/ver)
                                 ┌──────▼───────┐
                                 │  CodeVault   │  加密落盘，按 uin 分池
                                 └──────┬───────┘
                        ┌───────────────┴────────────────┐
                 ┌──────▼──────┐                  ┌───────▼────────┐
                 │ CodeBroker  │  取码/加锁/去重   │  AccountGuard  │  监听踢下线
                 └──────┬──────┘                  └───────┬────────┘
                        └────────────► 账号(code) ◄───────┘
                                        │
                                 ┌──────▼───────┐
                                 │  面板 / API   │  开关、通道状态、码池、补码流水
                                 └──────────────┘
```

### 组件职责

| 组件 | 职责 | 复用现有能力 |
|---|---|---|
| **CaptureHub** | 常驻 MITM、多监听地址、会话自动续期、通道识别 | `core/src/capture/*`（mitm-proxy、ca、ip-utils、session-store） |
| **CodeVault** | Code 加密存储、按 uin 建池、TTL/保留策略 | 新增（`data/code-vault/`） |
| **CodeBroker** | 取码（最新优先）、单飞锁、去重、消费标记 | 新增 |
| **AccountGuard** | 订阅 `account_kicked` / `ws_reconnect_failed`，自动补码+重启，退避 | `worker.js:onKickout`、`worker-manager` |
| **面板/API** | 开关、通道、码池、流水 | `panel/panel.ps1` + `panel/web/index.html` |

## 2. 工作流程

### 2.1 首次 / 新增账号（一次性配置）

```
手机 Wi-Fi 代理 = <面板显示的地址>:18000
手机安装并信任 CA 证书（面板一键下载）
打开 QQ 农场 → CaptureHub 抓到 code/openID/指纹
        → CodeVault 入库（status=active）
        → 自动建档（uin 已存在则只更新 code）→ worker 启动 → 上线
```

### 2.2 日常在线（0 操作）

Worker 自己维持与 `gate-obt.nqf.qq.com` 的 WS 与会话，**Code 不参与**。此阶段取码器完全静默。

### 2.3 被顶下线（关键场景）

```
worker 检测 kickout → 发 account_kicked
        → AccountGuard：账号标记 offline(kicked)
        → CodeBroker：取该 uin 最新 active 码（原子消费，标记 used）
             ├─ 有码 → 更新账号 code（POST /api/accounts）→ 重启 worker → 成功：记 used / 失败：记 invalid 并退避
             └─ 无码 → 进入 waiting_code，面板红点 +（可选）推送提醒"请打开一次农场"
                       一旦任意设备抓到该 uin 的新码，立刻自动恢复
```

### 2.4 周期性保活（可选）

对**当前在线**的账号不做任何探活（见边界 B4）；只对**离线账号**在等待期间做低频重试（默认 5 分钟一次）。

## 3. Code 的获取与存储

### 3.1 获取（三种来源，统一入口 `POST /api/code/push` 的内部口径）

| 来源 | 触发 | 是否自动 |
|---|---|---|
| `capture`（主） | 设备经代理打开农场 | ✅ 全自动 |
| `manual` | 面板/账号页粘贴 | 半自动（兜底） |
| `wx-auto` | 微信扫码登录后 `getFarmCode` | ✅ 仅微信平台 |

### 3.2 存储

- 位置：`data/code-vault/vault.json.enc`
- 加密：AES-256-GCM，密钥 `data/code-vault/key.bin`（首次生成，ACL 仅当前用户）；可选 Windows DPAPI 包裹
- 记录结构：

```json
{
  "id": "c_01HQ...",
  "uin": "775017308",
  "openid": "",
  "platform": "qq",
  "os": "iOS",
  "ver": "1.2.3_20260101",
  "code": "<明文仅内存/加密盘>",
  "channel": "phone-客厅",
  "channelIp": "192.168.1.23",
  "obtainedAt": 1792550000000,
  "usedAt": 0,
  "status": "active",            // active | used | invalid
  "lastError": ""
}
```

- 保留策略：每 uin 最多 `poolSizePerUin=5` 条；只保留 `active` + 最近 3 条 `used`；`invalid` 保留 24h 供排查
- 输出（面板）一律**脱敏**：只显示前 4 位 + 后 4 位

## 4. 多设备 / 多地点

| 场景 | 处理 |
|---|---|
| 多台设备各自登录农场 | 每台设备一个 **channel**（按来源 IP 识别，可命名备注）；码按 uin 汇总 |
| 同一 uin 多设备都抓到码 | 取 `obtainedAt` 最新的一条；旧的标 `superseded`（不立即删，防误判） |
| 换地点（公司/家里/4G） | 监听 `0.0.0.0`（LAN）+ Tailscale 地址；手机只要还能连到代理即可，**代理地址变化由面板展示** |
| 设备指纹 | 入库存 `platform/os/ver`；重启账号时沿用原指纹，避免风控差异 |
| 代理不可达 | 该 channel 标 `offline`（最近一次成功抓码距今 > `channelStaleMin=120` 分钟）；面板提示"该设备代理未生效" |

> 不建议公网暴露代理（见 B6）。跨网络用 **Tailscale** 最省事，项目里已有 Tailscale 地址广播。

## 5. 登录态失效检测与异常处理

### 5.1 检测手段（按可靠性排序）

| 手段 | 说明 | 是否打扰在线会话 |
|---|---|---|
| `account_kicked` 事件 | worker `onKickout` 已有，含 reason | 否 |
| `ws_reconnect_failed` | 连续重连失败（现有 30s 心跳判定） | 否 |
| 业务调用连续失败 | 拉土地/好友连续 N 次失败 | 否 |
| **主动探活（禁用）** | 用同 uin 的 code 另开 WS | **会顶掉在线会话 → 禁止** |

### 5.2 异常矩阵

| 异常 | 判定 | 处理 |
|---|---|---|
| CA 未信任 | 代理有 CONNECT 但 TLS 握手失败/无业务请求 | channel 标 `cert-issue`，面板给"重新下载证书" |
| 抓到空 code / 噪声 | extractor 长度规则已过滤 | 丢弃并计数，不计入失败 |
| code 无效 | 用该码连接被拒（close/401/handshake 失败） | 标 `invalid`，退避后重试或等新码 |
| 池空 | 该 uin 无 active | `waiting_code` + 提示，不静默 |
| 并发补码 | 同 uin 多个 kick 事件 | `CodeBroker` 单飞锁，串行化 |
| 多设备抢码 | 两设备同时抓到 | 原子消费，后到的留作备用 |
| 退避超限 | 连续失败 ≥ `maxAutoRetry=5` | 停止自动，转"待人工"，面板显式提示 |

## 6. 接口（新增，`core`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/code/hub` | `{enabled, mode, apiPort, proxyPort, channels[], sessionExpiresInSec}` |
| POST | `/api/code/hub/start` \| `/stop` | 常驻抓包开关 |
| GET | `/api/code/pool?uin=` | 码池（脱敏）+ 统计（active/used/invalid、最近抓码时间） |
| POST | `/api/code/push` | 外部注入 `{uin?, code, platform, source, channel?}` |
| POST | `/api/code/consume` | 内部：`{accountId, reason}` → `{ok, code}` 或 `{ok:false, reason:'empty'}` |
| GET | `/api/code/events?limit=50` | 补码流水（时间/账号/来源/结果/退避次数） |
| POST | `/api/code/heartbeat` | 设备侧可选，用于 channel 在线判定 |

> 现有 `/api/capture/sessions*`、`/api/capture/config` 保持不变，抓包器直接复用。

## 7. 可配置参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `codeFetcher.enabled` | `true` | 总开关 |
| `codeFetcher.mode` | `embedded` | `embedded`（主程序内）/ `standalone`（capture-server） |
| `codeFetcher.apiPort` | `8450` | 仅 standalone |
| `codeFetcher.proxyPort` | `18000` | MITM 端口 |
| `codeFetcher.listen` | `0.0.0.0` + Tailscale | 监听地址 |
| `codeFetcher.sessionTtlMs` | `3600000` | 会话 TTL（现有默认 1h） |
| `codeFetcher.renewBeforeSec` | `300` | 到期前自动续期 |
| `codeFetcher.captureHosts` | `*.nqf.qq.com, q.qq.com, ...` | 只对这些域解密，其它透传 |
| `codeFetcher.poolSizePerUin` | `5` | 每 uin 保留条数 |
| `codeFetcher.minCodeAgeSec` | `30` | 入库 30s 内的码才认为是"新鲜"（防抖） |
| `codeFetcher.allowUsedRetry` | `false` | 是否允许复用 used 码（谨慎） |
| `codeFetcher.kickBackoffMin` | `[1,5,15,30,60]` | 被踢后重试退避（分钟） |
| `codeFetcher.maxAutoRetry` | `5` | 超限转人工 |
| `codeFetcher.channelStaleMin` | `120` | 通道"失联"判定 |
| `codeFetcher.notify` | `off` | `off` / `qq`（用已有账号发消息）/ `email`（现有 SMTP） |
| `codeFetcher.allowPublic` | `false` | 是否允许公网监听（默认禁止） |
| `codeFetcher.channelWhitelist` | `[]` | 允许的 channel IP 段（空=不限，仅 LAN/Tailscale 内） |

## 8. 关键输入 / 输出

**输入**
1. 抓包事件：`{code, openID, host, platform/os/ver, sourceIp, at}`（来自 `code-extractor`）
2. 踢下线事件：`{accountId, uin, reason, at}`
3. 人工/外部推码：`POST /api/code/push`
4. 账号元数据：`{accountId, uin, platform, fingerprint}`

**输出**
1. `vault` 记录（加密落盘）
2. 账号更新：`code`（+ 必要时 `fingerprint`）
3. 补码流水 + 面板状态（通道/池/事件）
4. 可选通知（QQ 自消息 / 邮件）

## 9. 边界条件（务必遵守）

| 编号 | 边界 | 处理 |
|---|---|---|
| B1 | **Code 有效期未公开** | 不假设 TTL；一律"最近优先 + 用后即验"，失败标 invalid |
| B2 | 同一 code 并发消费 | `CodeBroker` 原子消费（单飞锁 + 状态 CAS） |
| B3 | **禁止主动探活** | 用同 uin 的码另开连接会顶掉在线会话，只做"被动检测" |
| B4 | 证书必须被设备信任 | 提供一键下载 + iOS/Android 安装指引；未信任时 channel 标 `cert-issue` |
| B5 | 只解密目标域 | `captureHosts` 白名单，其它域原始 TCP 透传，不记录内容 |
| B6 | 代理不能公网裸奔 | 默认 LAN/Tailscale；`allowPublic=false`；白名单 + 仅允许 CONNECT 目标域 |
| B7 | 池空不能静默 | 显式 `waiting_code` 状态 + 面板红点 + 可选通知 |
| B8 | 同一 uin 多条账号记录 | 以 uin 归并取码，避免重复消费 |
| B9 | 设备长期不开农场 | 池会耗尽 → 只能提示；这是物理限制，不做假承诺 |
| B10 | 明文码落盘风险 | 加密存储 + 面板脱敏 + 文件 ACL |

## 10. 验收标准

| # | 项 | 判定 |
|---|---|---|
| V1 | 常驻抓包开关 | 面板开启后 `proxyPort` 监听；关闭后释放，无残留 |
| V2 | 会话自续期 | 运行 > 1h 后仍能抓到码（TTL 到期未失效） |
| V3 | 自动入库 | 手机打开农场 → 5s 内码池出现新记录（active） |
| V4 | 自动建档/更新 | 新 uin 自动建档；已存在 uin 只更新 code，不重复建 |
| V5 | 被踢自动补码 | 手动 kick → 30s 内账号用池内码自动恢复上线 |
| V6 | 池空提示 | 清空池后 kick → 账号进入 `waiting_code`，面板可见提示，不反复重试刷屏 |
| V7 | 退避与转人工 | 连续失败 5 次后停止自动，事件流有记录 |
| V8 | 多设备 | 两台设备各自 channel 可见；同 uin 取最新码 |
| V9 | 脱敏 | 面板/接口不出现完整 code（仅前4后4） |
| V10 | 加密落盘 | `vault.json.enc` 无明文；删除 key 后不可解 |
| V11 | 无探活副作用 | 在线账号在整个验收过程中不掉线 |
| V12 | 兼容旧流程 | 原「抓包登录」按会话模式仍可用 |

## 11. 实施拆分（建议按阶段交付）

| 阶段 | 内容 | 价值 |
|---|---|---|
| **P1** | CodeVault + CodeBroker + `/api/code/*` + 面板「码池」卡片 | 码可见、可手工推、可被消费 |
| **P2** | CaptureHub 常驻（embedded）+ 自动入库 + 会话续期 + 通道识别 | 日常 0 操作 |
| **P3** | AccountGuard：踢下线自动补码 + 退避 + `waiting_code` 状态 | 被踢 0 操作 |
| **P4** | 通知（QQ 自消息/邮件）+ 事件流 + 稳定性打磨 | 池空时能提醒到人 |

每阶段独立提交、独立验收；P1 不改变现有行为，风险最低。

---

## 12. 与现有「抓包登录」的关系

- 现有按会话抓包（`/api/capture/sessions`）**保留**：用于一次性新增账号/多账号批量添加
- 取码器 = **常驻版 + 码池 + 自动编排**，与按会话模式**共用同一套 capture 内核**
- 两者可同时存在：按会话的任务不受常驻 hub 影响（不同 session）
